# Задача для Codex: Реализовать этап M11 — LIVE: коннекторы ордеров, управление позициями, риск

**Спецификация**: см. `README.md`, `./docs/TECH_STYLE_GUIDE.md`,
`./docs/stages/M11_LIVE_TRADING.md`, диаграммы в `./docs/diagrams/**` (sequence + flows),
особенно `m11_live_place_order`, `m11_live_trailing`, `m11_live_reconcile`.

> В этой задаче **не требуется** рефакторить ранее созданный код во всём репозитории —
> применяй правила `TECH_STYLE_GUIDE.md` только к новому коду M11.

## Инварианты (из TECH_STYLE_GUIDE)

* Java 25; Spring Boot 3.x; **jOOQ‑only** (запрещено добавлять Spring Data JPA).
* Lombok; MapStruct (имплементации генерятся при билде).
* springdoc-openapi-starter-webmvc-ui (Swagger UI); Spring Security (JWT; dev можно упростить).
* Конфиги: `application.yaml` (dev/prod), `docker-compose.yaml` (PostgreSQL). **Без триггеров** в БД.
* Все версии зависимостей — через `<properties>` в `pom.xml`.
* Слои: client/domain/api/persistence. **Маппинг только через domain**.
* Канонические таймфреймы — в YAML (canonical → per‑exchange mapping); **только закрытые свечи**; UTC.
* Стиль нового кода: одна переменная на строку; `{}` после `if`; аннотации **над** полями; строки → `Constants.*`; конечные значения → `enum`.
* Коды ошибок (dot‑нотация) и исключения: `ServiceException`, `UnexpectedException`.
* Проверки: `Objects.isNull/nonNull`, `Objects.equals`, `BooleanUtils.isFalse`, `CollectionUtils.isEmpty/isNotEmpty`.
* В миграциях — `COMMENT ON TABLE/COLUMN` **на всё**; в persistence‑моделях — **Javadoc на класс и поля**.

## Цели M11

1. Реализовать **унифицированный слой исполнения ордеров** (Execution Adapter) для нескольких бирж.
2. Построить **LiveTradingService**: принимать решения из M10 (quorum_decision_event) → формировать заявки, удерживать состояние позиции, вести trailing SL/TP/безубыток.
3. Внедрить **RiskService**: лимиты (плечо ≤ 10, isolated, риск на сделку ≤1%, макс. количество одновременных позиций, дневной/серийный лосс), **авто‑пауза** торговли при N убыточных подряд до ручного разбора.
4. Реализовать **ReconcileService**: регулярная сверка локального состояния с биржей (ордера/позиции), авто‑исправление рассинхронизаций.
5. Обеспечить **идемпотентность и аудит**: уникальные `client_order_id`, журнал событий по ордерам, снимки позиции, объяснимость действий.

## Что реализовать

### 1) Execution Adapter (интерфейс + реализации)

* `ExecutionAdapter` (интерфейс):

  * `createOrder(domain.NewOrder)` → `OrderAck`
  * `cancelOrder(exchangeOrderId|clientOrderId)` → `CancelAck`
  * `modifyOrder(modifySpec)` → `ModifyAck`
  * `getOrder(exchangeOrderId|clientOrderId)` → `OrderSnapshot`
  * `listOpenOrders(exchangeInstrument)` → `List<OrderSnapshot>`
  * `getPositions()` → `List<PositionSnapshot>`
  * Поддержать режимы: `PAPER | TESTNET | LIVE` (читается из конфига `app.execution.mode`).
* `OkxExecutionAdapter` (первая реализация): клиентские модели в `client/*`, маппинг → domain, подпись/таймауты/ретраи по конфигу.
* Паттерны: backoff, rate‑limit, обработка идемпотентности по `client_order_id`.

### 2) Доменная модель ордера/позиции (rich)

* `Order`: `clientOrderId`, `exchangeOrderId?`, `exchangeInstrumentId`, `side(LONG|SHORT)`, `type (MARKET|LIMIT|STOP|TRAILING_STOP)`, `qty`, `price?`, `sl?`, `tp?`, `timeInForce`, `status(NEW|SUBMITTED|PARTIALLY_FILLED|FILLED|CANCELED|REJECTED|EXPIRED)`, `reason`.
* `Position`: `size`, `avgPrice`, `leverage`, `isolated=true`, `sl/tp`, `unrealizedPnl`, `stateVersion` (для оптимистичных апдейтов).
* Идемпотентный ключ `client_order_id = hash(strategy, exchangeInstrument, ts, action)`.

### 3) LiveTradingService

* Источник входа — события из `quorum_decision_event` (M10). Для каждого `(exchange_instrument, timeframe)` — **один писатель** (single‑writer) очереди команд.
* Алгоритм:

  1. Получить последнее решение кворума на `ts`: `ENTER/EXIT/REVERSE/MODIFY_SLTP/HOLD`.
  2. Вызвать `RiskService.preCheck(...)` (см. ниже). При нарушении — логировать `reason` и **не исполнять**.
  3. Преобразовать решение в доменную команду (`NewOrder` / `Cancel` / `Modify`).
  4. Отправить в `ExecutionAdapter`, получить `Ack`, обновить локальные таблицы (см. БД).
  5. Для открытой позиции — поддерживать **trailing SL** и **breakeven** по правилам конфигурации (из M9/M10).
* Параметры задержек/повторов/таймаутов — из `application.yaml`.

### 4) RiskService

* Ограничения (читаются из `risk_params` и/или `application.yaml`):

  * `riskPerTradePct ≤ 1.0`; `leverage ≤ 10`;
  * `isolated = true` всегда;
  * `maxConcurrentPositions`, `dailyLossLimitR`, `maxLosingStreak`.
* Поведение:

  * На вход `ENTER` — проверять лимиты, доступный баланс, ожидаемый SL (расчёт размера позиции).
  * Вести счётчики лоссов/дневного результата; при превышении — **ставить флаг HALT** для инструмента/всей системы.
  * Предоставить эндпоинт **ручного возобновления** торговли после разбора.

### 5) ReconcileService

* Периодически (по расписанию) сравнивать локальные `order_state`/`position_state` с данными биржи:

  * Доставлять пропущенные `fills`;
  * Закрывать локально «висящие» ордера;
  * Корректировать `position_state` (разногласия фиксировать как `UnexpectedException`, если критично).

### 6) БД (SQL‑миграции, без триггеров; **COMMENT ON** на всё)

1. `order_event` — **append‑only журнал ордеров**

   * `id BIGSERIAL PK`
   * `client_order_id TEXT NOT NULL` — уникально по системе (UK)
   * `exchange_order_id TEXT NULL` — когда известен
   * `exchange_instrument_id BIGINT NOT NULL`
   * `ts_utc TIMESTAMP NOT NULL`
   * `event_type TEXT NOT NULL` — enum: `REQUESTED|SUBMITTED|ACCEPTED|PARTIALLY_FILLED|FILLED|CANCELED|REJECTED|EXPIRED|MODIFIED`
   * `payload JSONB NOT NULL` — снимок доменной команды/ответа биржи
   * Индексы: по `client_order_id`, `exchange_order_id`, `exchange_instrument_id, ts_utc`
2. `order_state` — **снимок текущего состояния ордера**

   * `client_order_id TEXT PK`, `exchange_order_id TEXT NULL`, `status TEXT NOT NULL`, `filled_qty NUMERIC(...) NOT NULL`, `avg_fill_price NUMERIC(...) NULL`, `updated_at TIMESTAMP NOT NULL`
3. `fill_event` — события исполнений

   * `id BIGSERIAL PK`, `client_order_id TEXT NOT NULL`, `ts_utc TIMESTAMP NOT NULL`, `qty NUMERIC(...) NOT NULL`, `price NUMERIC(...) NOT NULL`, `fee NUMERIC(...) NOT NULL`
4. `position_state` — **единственный источник истины по позиции** (на уровне `(exchange_instrument)`)

   * `exchange_instrument_id BIGINT PK`, `size NUMERIC(...) NOT NULL`, `avg_price NUMERIC(...) NULL`, `sl NUMERIC(...) NULL`, `tp NUMERIC(...) NULL`, `leverage INT NOT NULL`, `isolated BOOLEAN NOT NULL DEFAULT TRUE`, `updated_at TIMESTAMP NOT NULL`
5. `risk_halt_state` — флаги остановки торговли

   * `scope TEXT NOT NULL` — enum `GLOBAL|INSTRUMENT`
   * `exchange_instrument_id BIGINT NULL` (для `INSTRUMENT`)
   * `is_halted BOOLEAN NOT NULL`, `reason TEXT NOT NULL`, `updated_at TIMESTAMP NOT NULL`
   * UK: `(scope, exchange_instrument_id)`

> Все числовые scale/rounding — из конфига. Имена индексов `pk_/uk_/ix_`. Везде `COMMENT ON TABLE/COLUMN`.

### 7) Конфигурация (`application.yaml`)

```yaml
app:
  execution:
    mode: PAPER           # PAPER | TESTNET | LIVE
    requestTimeoutMs: 10000
    maxRetries: 3
    retryBackoffMs: 500
    rateLimitPerSecond: 4
  trailing:
    enabled: true
    atrPeriod: 14
    trail_k_atr: 1.0
    breakeven_at_r: 1.0
  risk:
    riskPerTradePct: 1.0
    leverageMax: 10
    isolated: true
    maxConcurrentPositions: 3
    dailyLossLimitR: 5.0
    maxLosingStreak: 3
  reconcile:
    enabled: true
    periodSec: 30
```

### 8) REST‑эндпоинты (Swagger)

* **Управление исполнением**

  * `POST /api/live/place` — `{ exchangeInstrumentId, side, type, qty, price?, sl?, tp?, tif? }`
  * `POST /api/live/cancel` — `{ clientOrderId? , exchangeOrderId? }`
  * `POST /api/live/modify` — `{ clientOrderId, newPrice?, newSl?, newTp? }`
* **Просмотр состояния**

  * `GET  /api/live/orders` — фильтры: `status?, exchangeInstrumentId?`
  * `GET  /api/live/positions` — текущее состояние позиций
  * `GET  /api/live/events` — события ордеров (пагинация)
* **Риск и пауза**

  * `POST /api/live/halt` — `{ scope: GLOBAL|INSTRUMENT, exchangeInstrumentId?, reason }`
  * `POST /api/live/resume` — `{ scope: GLOBAL|INSTRUMENT, exchangeInstrumentId? }`
  * `GET  /api/live/halt/state` — текущее состояние флагов
* **Сверка и здоровье**

  * `POST /api/live/reconcile/run` — разовая сверка сейчас
  * `GET  /api/live/connector/health` — пинги адаптеров бирж

### 9) Метрики/логи

* `live.order.requested/submitted/accepted/filled/partial/canceled/rejected/expired`
* `live.exchange.latency_ms`, `live.exchange.calls`, `live.exchange.retries`
* `live.position.size`, `live.position.pnl_unrealized`
* `live.risk.halt.active`, `live.risk.violations`
* `live.reconcile.fixed`, `live.reconcile.discrepancies`

### 10) Идемпотентность и конкуренция

* Для каждой серии `(exchange_instrument)` — **single‑writer** компонент (очередь команд) во избежание гонок.
* Все записи в БД — через уникальные ключи (например, `client_order_id`), апдейты `order_state` — оптимистичные (версионирование/`updated_at`).
* Повторные Acks/события от биржи — обрабатывать безопасно (дедуп по ключам).

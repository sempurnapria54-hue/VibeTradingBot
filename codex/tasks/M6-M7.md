# Задача для Codex: Реализовать этапы M6–M7

**Спецификация**: см. `README.md`, `./docs/TECH_STYLE_GUIDE.md`,
`./docs/stages/M6_INDICATOR_VALUES_EMA.md`, `./docs/stages/M7_INDICATOR_VALUES_OTHERS.md`,
диаграммы в `./docs/diagrams/**` (sequence + flows), особенно `m06_m07_indicators_fill`.

> В этой задаче **НЕ требуется** переписывать существующий код под TECH_STYLE_GUIDE во всём репозитории. Применяй правила гайда только к новому коду M6–M7.

## Инварианты (из TECH_STYLE_GUIDE)

* Java 25; Spring Boot 3.x; **jOOQ-only** (запрещено добавлять Spring Data JPA).
* Lombok; MapStruct (имплементации генерятся при билде).
* springdoc-openapi-starter-webmvc-ui (Swagger UI); Spring Security (JWT; dev можно упростить).
* Конфиги: `application.yaml` (dev/prod), `docker-compose.yaml` (PostgreSQL). **Без триггеров** в БД.
* Все версии зависимостей — через `<properties>` в `pom.xml`.
* Слои: client/domain/api/persistence. **Маппинг только через domain** (rich‑модель с методами).
* Канонические таймфреймы — в YAML (canonical → per‑exchange mapping), сравнение без нормализации в lower‑case; **только закрытые свечи**.
* Стиль нового кода: одна переменная на строку; `{}` после `if`; аннотации **над** полями; строки → `Constants.*`; конечные значения → `enum`.
* Коды ошибок (dot‑нотация) и исключения: `ServiceException`, `UnexpectedException`.
* Проверки: `Objects.isNull/nonNull`, `Objects.equals`, `BooleanUtils.isFalse`, `CollectionUtils.isEmpty/isNotEmpty`.
* В миграциях — `COMMENT ON TABLE/COLUMN` **на всё**; в persistence‑моделях — **Javadoc на класс и поля**.

## Что реализовать

### M6 — Значения индикаторов (EMA как «скелет» конвейера)

1. **IndicatorService (EMA)**

   * `fillEma(exchangeInstrumentId, timeframe, indicatorParamsRef)` — расчёт EMA по историческим свечам.
   * Стартовая точка: `indicator_checkpoint` или `coverage_start_utc` (учесть **warmup** из конфигурации/параметров).
   * Обновление буферов **строго ASC по барам**; warmup‑период не сохраняем.
   * Идемпотентность: `INSERT ... ON CONFLICT DO NOTHING` по ключу `(candle_id, indicator_params_id, version)`.
   * По завершении — `UPSERT indicator_checkpoint(last_ts)` для `(indicator, timeframe, exchange_instrument_id, indicator_params_id, version)`.
2. **Схема БД (если ещё не создана)**

   * `ema_values`: `id PK`, `candle_id FK`, `indicator_params_id FK`, `version INT`, `ema_value NUMERIC(50, <scale_from_config>)`, `created_at TIMESTAMP`.
   * `indicator_checkpoint`: `(indicator TEXT, timeframe_canonical TEXT, exchange_instrument_id BIGINT, indicator_params_id BIGINT, version INT, last_ts TIMESTAMP, updated_at TIMESTAMP)`; `UK` по перечисленным полям.
   * **Комментарии на все поля/таблицы**.
3. **Конфигурация (`application.yaml`)**

   ```yaml
   app:
     indicators:
       warmupBars:
         EMA: 100           # можно переопределять через indicator_params
       batchFlushBars: 200
       numeric:
         priceScale: 30
         mathRounding: HALF_UP
   ```
4. **REST‑эндпоинты (Swagger)**

   * `POST /api/indicators/fill/ema` — тело: `{ exchangeInstrumentId, timeframe, paramsRef }`.
   * `GET /api/indicators/checkpoint` — получить checkpoint по серии/индикатору.
5. **Метрики**

   * `indicators.ema.values.inserted`, `indicators.ema.checkpoint.updated`, `indicators.ema.skipped.warmup`.

### M7 — Масштабирование значений индикаторов (MACD/RSI/Stoch/BB/OBV)

Реализовать скелеты по той же схеме, что EMA:

1. **Индикаторы и поля**

   * **MACD**(12,26,9): `macd`, `signal`, `histogram`.
   * **RSI**(n): `rsi`.
   * **Stochastic**(k,d,smooth): `%K`, `%D`.
   * **Bollinger Bands**(period,σ): `basis`, `upper`, `lower`, `percent_b`, `bandwidth`.
   * **OBV**: `obv`.
2. **Таблицы** (если не были определены): `macd_values`, `rsi_values`, `stoch_values`, `bb_values`, `obv_values` — поля: `id PK`, `candle_id FK`, `indicator_params_id FK`, `version INT`, набор значений (см. выше), `created_at TIMESTAMP`; `UK(candle_id, indicator_params_id, version)`; **комментарии на всё**.
3. **Сервисные методы**

   * `fillMacd(...)`, `fillRsi(...)`, `fillStoch(...)`, `fillBb(...)`, `fillObv(...)` — одинаковая схема: checkpoint → загрузка свечей → буферы → вставки → checkpoint.
   * Математика — через `BigDecimal`/`MathContext`/`RoundingMode` из конфига, утилиты без `double`.
4. **REST‑эндпоинты**

   * `POST /api/indicators/fill/macd|rsi|stoch|bb|obv`.
5. **Метрики**

   * По каждому индикатору: `*.values.inserted`, `*.checkpoint.updated`, `*.skipped.warmup`.

## Требования к БД/миграциям

* Все новые таблицы/индексы — SQL без триггеров; **COMMENT ON TABLE/COLUMN** на всё.
* Уникальные ключи как описано; FK на существующие `candles` и `indicator_params`.
* Чекпоинты — UK `(indicator, timeframe_canonical, exchange_instrument_id, indicator_params_id, version)`.

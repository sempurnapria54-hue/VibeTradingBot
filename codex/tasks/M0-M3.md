# Задача для Codex: Реализовать этапы M0–M3

**Спецификация**: см. `README.md`, `./docs/TECH_STYLE_GUIDE.md`, `./docs/stages/M0_BOOTSTRAP.md`, `./docs/stages/M1_MODELS_AND_MAPPERS.md`, `./docs/stages/M2_SCHEMA_AND_MIGRATIONS.md`, `./docs/stages/M3_EXCHANGE_INTEGRATION.md`, а также диаграммы в `./docs/diagrams/**`.

## Инварианты

* Java 25; Spring Boot 3.x.
* **jOOQ‑only** (запрещено добавлять Spring Data JPA).
* Lombok; MapStruct (генерация имплементаций при билде).
* springdoc‑openapi‑starter‑webmvc‑ui (Swagger UI).
* Spring Security (JWT; dev можно упростить).
* Конфиги: `application.yaml` (dev/prod), `docker-compose.yaml` (PostgreSQL). **Без триггеров** в БД.
* Все версии зависимостей — через `<properties>` в `pom.xml`.
* Слои моделей: client/domain/api/persistence. **Маппинг только через domain** (rich‑модель с методами).
* Канонические таймфреймы — в YAML (canonical → per‑exchange mapping). **Без статуса свечей**. `coverage_end_utc` — учесть.
* Стиль: одна переменная на строку; всегда `{}` после `if`; аннотации над полями — **на строке выше**.

## Дополнительные правила стиля (исправить во всём создаваемом коде)

* Все строковые литералы → в `util/Constants.java` (вложенные классы по доменам: `Errors`, `Fields`, `Api`, ...).
* Конечные наборы значений → `enum` (например, статусы, канон. таймфреймы и пр.).
* Коды ошибок — в **dot‑нотации**: `insufficient.balance`, `order.rejected.exchange`, и только через константы.
* Ввести исключения: `ServiceException(code,message)` и `UnexpectedException(code,message)`.
* Проверки: `Objects.isNull/nonNull`, `Objects.equals(a,b)`, `BooleanUtils.isFalse(flag)`, `CollectionUtils.isEmpty/isNotEmpty`.
* BigDecimal scale/precision/rounding — из `application.yaml` (не хардкодить условия вида `amount.scale() > 30`).
* Persistence‑модели — **Javadoc на класс и поля**.
* MapStruct мапперы — декларативно, `unmappedTargetPolicy = ReportingPolicy.ERROR`.

## Что нужно сделать в M0–M3

1. **M0 — Bootstrap**: Maven (все версии в `<properties>`), плагины (jOOQ codegen, mapstruct-processor), базовый каркас пакетов, `.editorconfig`, `springdoc`, Security (JWT dev), DevTools.
2. **M1 — Модели и мапперы**: слои client/domain/api/persistence; маппинг через MapStruct; `Constants`/`Enums`; Javadoc в persistence.
3. **M2 — БД и миграции**: SQL без триггеров; **COMMENT ON TABLE/COLUMN** на всё; схемы под candles/coverage/exchange/instrument/exchange_instrument/params; индексы и ограничения; `docker-compose.yaml` (PostgreSQL); профиль jOOQ codegen.
4. **M3 — Интеграция с биржей (данные)**: каркас коннектора (интерфейсы, модели, сигнатуры), конфиги канонических ТФ и маппингов, Health/Config/Onboarding базовые контроллеры.

## Критерии готовности

* `mvn -Pdev -DskipTests clean package` успешно.
* `docker compose up -d db` поднимает PostgreSQL; миграции применяются; jOOQ codegen проходит.
* Swagger UI доступен; базовые контроллеры и коннектор присутствуют.
* Стиль и правила из `TECH_STYLE_GUIDE.md` **выполнены** (константы/enum/исключения/проверки/MapStruct/Javadoc).

## Команды проверки (выполнить перед созданием PR)

```bash
docker compose up -d db
./mvnw -Pdev -DskipTests clean package
```

## Ограничения

* **Нельзя** добавлять Spring Data JPA — использовать **только jOOQ**.

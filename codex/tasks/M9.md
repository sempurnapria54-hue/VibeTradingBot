## Цель M9

Реализовать **оффлайн‑симулятор исполнения** поверх исторических свечей и сгенерированных сигналов (M8),
который считает метрики эффективности. Поддержать **три типа горизонтов** (triple‑barrier — основной):

* **Triple‑Barrier**: `TP = k_tp * ATR`, `SL = k_sl * ATR`, `TimeStop = H` баров. Метка результата — что сработало первым.
* **Time‑Horizon (bars)**: фиксация результата через `H` баров.
* **Vol‑Horizon**: выход при достижении ±`k_atr * ATR`.

Каждый запуск фиксирует **снимки конфигов** (immutable `*_params`) и сохраняет результаты как **append‑only** события.

## Что реализовать

### 1) Таблицы (SQL‑миграции, полные COMMENT ON)

1. `backtest_run`

   * `id BIGSERIAL PK`
   * `exchange_instrument_id BIGINT NOT NULL`
   * `timeframe_canonical TEXT NOT NULL`
   * `from_utc TIMESTAMP NOT NULL`, `to_utc TIMESTAMP NOT NULL`
   * `signal_types TEXT[] NOT NULL` — список типов сигналов, участвующих в симуляции (например, только `EMA_TREND` или набор)
   * `signal_params_id BIGINT NOT NULL` — ссылка на immutable параметры сигналов (если несколько — указать стратегию в `params_json`)
   * `quorum_params_id BIGINT NULL` — если тестируем составной score (см. ниже)
   * `risk_params_id BIGINT NOT NULL` — риск‑модель (RR, макс. лосс подряд, плечо, isolated)
   * `exchange_params_id BIGINT NOT NULL` — комиссии/фандинг/ограничения
   * `backtest_params_id BIGINT NOT NULL` — immutable конфиг M9 (latency, slippage, TP/SL, горизонты…)
   * `params_json JSONB NOT NULL` — канонический снимок всех параметров
   * `created_at TIMESTAMP NOT NULL`
   * UK: `UK(backtest_params_id, exchange_instrument_id, timeframe_canonical, from_utc, to_utc)` — для идемпотентности однотипных прогонов

2. `backtest_trade`

   * `id BIGSERIAL PK`, `run_id BIGINT NOT NULL FK→backtest_run`
   * `signal_id BIGINT NULL` — если вход инициирован конкретным событием `signal_event`
   * `entry_ts TIMESTAMP NOT NULL`, `exit_ts TIMESTAMP NOT NULL`
   * `side TEXT NOT NULL` — enum `LONG|SHORT`
   * `entry_price NUMERIC(50, <scale>) NOT NULL`, `exit_price NUMERIC(50, <scale>) NOT NULL`
   * `pnl_r NUMERIC(20,10) NOT NULL` — результат в `R`
   * `fees NUMERIC(20,10) NOT NULL`, `slippage NUMERIC(20,10) NOT NULL`, `funding NUMERIC(20,10) NOT NULL`
   * `mae_r NUMERIC(20,10) NOT NULL`, `mfe_r NUMERIC(20,10) NOT NULL`
   * `which_hit_first TEXT NOT NULL` — enum `TP|SL|TIME|EXIT_RULE`
   * `time_to_event_bars INT NOT NULL`
   * `reason JSONB NOT NULL` — краткая трасса (какой сигнал/score/порог → вход; как двигался SL/TP/BE/Trail)
   * Индексы по `run_id`, `entry_ts`, `signal_id`

3. `backtest_equity_point`

   * `id BIGSERIAL PK`, `run_id BIGINT NOT NULL`, `ts TIMESTAMP NOT NULL`, `equity_r NUMERIC(20,10) NOT NULL`

4. `performance_aggregate`

   * `id BIGSERIAL PK`, `run_id BIGINT NOT NULL`
   * `trades INT NOT NULL`, `winrate NUMERIC(6,4) NOT NULL`
   * `profit_factor NUMERIC(12,6) NOT NULL`, `expectancy_r NUMERIC(12,6) NOT NULL`
   * `max_drawdown_r NUMERIC(12,6) NOT NULL`, `sharpe NUMERIC(12,6) NULL`, `sortino NUMERIC(12,6) NULL`
   * Доп. срезы (опционально): по дням недели, сессиям, ATR‑квантилям, тренд/флэт

> Все таблицы и поля снабдить **COMMENT ON**. Все числовые scale/rounding — из конфига.

### 2) Конфигурация (`application.yaml`)

```yaml
app:
  backtest:
    latencyBars: 1            # задержка исполнения (например, вход по следующей свече)
    slippageBps: 1.5          # проскальзывание в б.п.
    takerFeeBps: 5.0          # комиссия (taker); maker можно приравнять к 0/по конфигу
    fundingBpsPer8h: 0.8      # грубая модель funding за 8ч (для перпетуалов)
    horizons:
      bars: [1,3,5,10]
      volAtr: [1.0,1.5,2.0]
      tripleBarrier:
        tp_k_atr: 1.5
        sl_k_atr: 1.0
        time_bars: 5
    trailing:
      enabled: true
      atrPeriod: 14
      trail_k_atr: 1.0        # дистанция трейла в ATR
      breakeven_at_r: 1.0     # перевод в безубыток при MFE ≥ 1R
    position:
      leverageMax: 10
      isolated: true
      riskPerTradePct: 1.0
```

### 3) Сервис `BacktestService`

Реализовать оффлайн‑симулятор:

* **Материализация входов**:

  * По умолчанию: вход по событиям `signal_event` (фильтрация по `signal_types`, опционально — через экспериментальный `quorum_params_id` для составного score).
  * Применить латентность (`latencyBars`).
* **Размер позиции**: рассчитывать по `riskPerTradePct` и `SL` (в `R`).
* **Исполнение**:

  * Модель **triple‑barrier** (основная): `TP`, `SL`, `TimeStop`. Учитывать **trailing SL** и **breakeven** (если включены).
  * Модели **bars** и **volAtr** — как альтернативные режимы.
  * Комиссии, проскальзывание, funding — согласно конфигу.
* **Результаты**:

  * Для каждой сделки — записать `backtest_trade` с полями MAE/MFE (в `R`), `which_hit_first`, `time_to_event_bars`, `reason` (краткая трасса принятия входа/движения стопа).
  * Построить `backtest_equity_point` (по закрытиям баров) и `performance_aggregate`.
* **Идемпотентность**: при повторном запуске с теми же параметрами — находить существующий `backtest_run` (UK) и либо отказывать, либо создавать новый с новой версией (на усмотрение — опция `allowDuplicate`).

### 4) REST‑эндпоинты (Swagger)

* `POST /api/backtest/run` — тело: `{ exchangeInstrumentId, timeframe, fromUtc, toUtc, signalTypes[], paramsRef(s), quorumParamsRef?, riskParamsRef, exchangeParamsRef, backtestParams }`

  * Возвращает `run_id`.
* `GET  /api/backtest/{runId}/report` — агрегированные метрики (`performance_aggregate`) + сводка по конфигу.
* `GET  /api/backtest/{runId}/equity` — кривая капитала (список `equity_point`).
* `GET  /api/backtest/{runId}/trades` — постранично сделки (`backtest_trade`).
* `POST /api/backtest/suggest-quorum` — (опционально) на базе результатов `run_id` посчитать рекомендованные веса/пороги и вернуть **кандидат** `quorum_params` (без записи в БД).

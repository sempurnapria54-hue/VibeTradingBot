## Инварианты (из TECH_STYLE_GUIDE)

* В миграциях — `COMMENT ON TABLE/COLUMN` **на всё**; в persistence‑моделях — **Javadoc на класс и поля**.

## Цель M10

Построить **QuorumEngine** — слой, который агрегирует входящие **сигналы (M8)** по правилам и параметрам кворума
(веса, пороги, gatekeepers/penalty/bonus, debounce/cooldown), и выдаёт **торговые решения**: `ENTER`, `EXIT`, `REVERSE`, `MODIFY_SLTP`, `HOLD`.
Результат — **append‑only журнал решений** с подробной объяснимостью `reason` (вклад каждого сигнала/фильтра), пригодный
для аудита и последующего исполнения в M11 (LIVE).

## Что реализовать

### 1) Таблицы (SQL‑миграции, полные COMMENT ON)

1. `quorum_decision_event`

   * `id BIGSERIAL PK`
   * `exchange_instrument_id BIGINT NOT NULL` — FK
   * `timeframe_canonical TEXT NOT NULL`
   * `ts_utc TIMESTAMP NOT NULL` — момент принятия решения (UTC, обычно закрытие бара)
   * `action TEXT NOT NULL` — enum: `ENTER|EXIT|REVERSE|MODIFY_SLTP|HOLD`
   * `direction TEXT NULL` — `LONG|SHORT` (для `ENTER/REVERSE`, иначе `NULL`)
   * `score NUMERIC(10,6) NOT NULL` — итоговый агрегированный score кворума `[-1..+1]`
   * `threshold_enter NUMERIC(10,6) NOT NULL` — порог входа (из `quorum_params`)
   * `threshold_exit  NUMERIC(10,6) NOT NULL` — порог выхода (из `quorum_params`)
   * `quorum_params_id BIGINT NOT NULL` — FK на immutable параметры кворума
   * `version INT NOT NULL` — версия правил кворума
   * `position_state JSONB NOT NULL` — снимок состояния позиции (size/avgPrice/sl/tp/…)
   * `reason JSONB NOT NULL` — объяснимость (см. формат ниже)
   * `created_at TIMESTAMP NOT NULL`
   * Индексы: `(exchange_instrument_id, timeframe_canonical, ts_utc)`; по `action`

2. `quorum_checkpoint`

   * `quorum_params_id BIGINT NOT NULL`, `version INT NOT NULL`
   * `exchange_instrument_id BIGINT NOT NULL`, `timeframe_canonical TEXT NOT NULL`
   * `last_ts TIMESTAMP NOT NULL`, `updated_at TIMESTAMP NOT NULL`
   * UK: `(quorum_params_id, version, exchange_instrument_id, timeframe_canonical)`

> Напоминание: `quorum_params` уже существует (immutable; M2). Использовать подход `resolveOrCreate`.

### 2) Конфигурация (`application.yaml`)

```yaml
app:
  quorum:
    debounceBars: 1            # защита от дрожания решения
    cooldownBars: 0            # подавление повторного ENTER/REVERSE вблизи
    numeric:
      scoreScale: 6
      rounding: HALF_UP
```

### 3) Формат `reason` (объяснимость)

```json
{
  "inputs": [
    { "type": "EMA_TREND", "tf": "1 hour", "score": 0.42, "weight": 0.30, "contrib": 0.126,
      "fields": { "ema10": "...", "ema20": "..." } },
    { "type": "MACD_IMPULSE", "tf": "15 minutes", "score": 0.35, "weight": 0.25, "contrib": 0.0875,
      "fields": { "hist": "..." } }
  ],
  "filters": [
    { "name": "HTF_TREND_GATE", "mode": "gate", "passed": true, "detail": { "emaSlope": "..." } },
    { "name": "SQUEEZE_MODE", "mode": "penalty", "factor": 0.6 }
  ],
  "aggregation": {
    "rawScore": 0.77,
    "afterFilters": 0.54,
    "thresholds": { "enter": 0.50, "exit": 0.15 }
  },
  "action": "ENTER",
  "direction": "LONG",
  "notes": "debounce ok; no cooldown; position flat"
}
```

### 4) Сервис: `QuorumService` / `QuorumEngine`

Реализовать инкрементальную агрегацию на каждой свече (ASC):

* `decide(exchangeInstrumentId, timeframe, quorumParamsRef)` —

  1. `resolveOrCreate(quorum_params)` по канону (type, timeframe, version, canonical_json).
  2. Выбрать из `signal_event` последние релевантные сигналы (M8) для текущей `ts` и требуемых ТФ.
  3. Посчитать **взвешенную сумму** `S = Σ w_i * score_i` (веса — из `quorum_params`).
  4. Применить **фильтры**: `gate` (жёсткое отклонение) и `penalty/bonus` (мультипликативная корректировка `S`).
  5. Определить `action` по порогам и текущему **снимку позиции** (из `position_state` компонента; можно хранить позицию в памяти или в таблице `position_state` — по твоему каркасу):

     * Если позиции нет и `S ≥ threshold_enter` → `ENTER (dir=sign(S))`.
     * Если позиция открыта и `|S| ≤ threshold_exit` → `EXIT`.
     * Если позиция открыта в противоположную сторону и `S` пересёк порог в другую сторону → `REVERSE`.
     * Если позиция есть и `S` усилился/ослаб — разрешить `MODIFY_SLTP` (правила: на этом этапе достаточно заготовки, фактические ордеры — в M11).
     * Иначе `HOLD`.
  6. Учитывать `debounce/cooldown` из конфига.
  7. Сформировать `reason` и **вставить** `quorum_decision_event` (идемпотентно: на `ts` максимум одно решение для `(exchange_instrument, timeframe, quorum_params_id, version)`).
  8. Обновить/вставить `quorum_checkpoint(last_ts)`.

* Пакетный режим: `decideRange(exchangeInstrumentId, timeframe, quorumParamsRef, fromUtc, toUtc)` — массовая агрегация (для ретроспективного анализа).

### 5) REST‑эндпоинты (Swagger)

* `POST /api/quorum/decide` — `{ exchangeInstrumentId, timeframe, quorumParamsRef }` — инкрементальная агрегация.
* `POST /api/quorum/decide-range` — `{ exchangeInstrumentId, timeframe, quorumParamsRef, fromUtc, toUtc }`.
* `GET  /api/quorum/latest` — `exchangeInstrumentId, timeframe, limit?` — последние `N` решений (с `reason`).
* `GET  /api/quorum/checkpoint` — получить checkpoint по серии и параметрам.
* `POST /api/quorum/params/activate` — принять **кандидата** `quorum_params` (например, из M9 `/suggest-quorum`) и создать **новую immutable** запись с версией; вернуть её `id`.

### 6) Enum/константы

* `QuorumAction` (enum): `ENTER`, `EXIT`, `REVERSE`, `MODIFY_SLTP`, `HOLD`.
* `Direction` (enum): `LONG`, `SHORT`, `NEUTRAL` (повторно использовать общий enum).
* Коды ошибок/имена полей — в `util/Constants`.

### 7) Метрики

* `quorum.decisions.total{action=...}` — количество решений по типам.
* `quorum.score.raw` / `quorum.score.filtered` — гистограммы score.
* `quorum.checkpoint.updated` — обновления чекпоинта.

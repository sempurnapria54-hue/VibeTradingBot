# M5 — Целостность истории (валидации, мониторинг, автодокачка)

**Цель этапа.** Обеспечить **целостность** исторических данных свечей, своевременно находить и устранять проблемы: пропуски баров, разрывы сетки таймфрейма, дубликаты, неверные OHLC/объёмы, дрейф времени, рассинхронизацию с биржей. Реализовать **мониторинг**, **автодокачку** и обновление **покрытий** (см. M2), на базе коннекторов и загрузчиков из M3–M4.

> Стадия не считает индикаторы и не генерирует сигналы — только **контроль качества исторических свечей** и процедуры восстановления.

---

## Scope / Out of Scope

**Входит:**

* Набор проверок целостности для каждой серии `history_group (exchange_instrument × timeframe_canonical)`.
* Отчёт о статусе целостности по связке (`exchange_instrument`) и глобально по системе.
* Автоматическая/ручная **докачка дыр** (повторное использование сценариев M4) и пересчёт покрытий.
* Метрики и алерты (Prometheus/Alertmanager).
* REST‑эндпойнты для запуска проверок, просмотра отчётов, автодокачки и пересчёта покрытий.

**Не входит:**

* Изменение схемы БД (см. M2), расчёт индикаторов/сигналов (M4+/M6+).

---

## Ключевые инварианты данных

1. **Закрытость баров:** все записи в `candles` — только **закрытые** свечи.
2. **Сетка времени:** для серии с каноническим ТФ `Δt` каждый `timestamp_utc` кратен шагу, разрывы недопустимы в секции, которая участвует в покрытии.
3. **Уникальность:** `(history_group_id, timestamp_utc)` уникальны; дубликаты невозможны.
4. **OHLC‑инварианты:** `low ≤ min(open, close) ≤ max(open, close) ≤ high`.
5. **Объёмы:** `volume_coin ≥ 0`, `volume_currency ≥ 0` (если не `NULL`).
6. **UTC и дрейф:** `timestamp_utc ≤ nowExchange() + tolerance`.
7. **Покрытия:**

    * Локально: `history_group.coverage_start_utc` указывает начало непрерывного участка по серии.
    * Сводно: `exchange_instrument_coverage.coverage_start_utc = max(локальных стартов)`, `coverage_end_utc = min(последних закрытых)` или `NULL`.

---

## Компоненты

* **CheckHistoryConsistencyService** — выполняет проверки, формирует отчёты, создаёт задания на докачку.
* **GapFiller** — оркестратор сценариев докачки (повторное использование M4 сервисов), batched, идемпотентно.
* **CoverageRecalculator** — пересчёт локальных и сводных покрытий после фиксов.
* **ConsistencyReporter** — агрегация и выдача статусов в REST/метрики.

---

## Проверки (per‑series)

> Все проверки выполняются для конкретной серии `history_group`. На уровне связки даётся агрегированный итог.

1. **Проверка сетки времени**

    * Ожидаемая сетка: `generate_series(min_ts, max_ts, Δt)` (где `Δt` — шаг канонического ТФ).
    * Находим отсутствующие `missing = expected − actual`. Если `missing ≠ ∅`, фиксируем «дыры».

2. **Проверка выравнивания отметок**

    * Каждая метка `ts` должна удовлетворять `ts % Δt == 0` (с учётом таймзоны UTC). Иначе — ошибка нормализации.

3. **Дубликаты**

    * Защищено `UNIQUE`, но отчёт показывает попытки дублей (по числу конфликтов при вставках) и аномалии, если ключ не включён.

4. **OHLC/объёмы**

    * Валидируем неравенства и неотрицательность объёмов.

5. **Граница «сейчас»**

    * Последний бар не должен выходить в будущее относительно `ExchangeClock.nowExchange()`.

6. **Согласованность между ТФ** (опционально)

    * Для диагностики: суммарные объёмы/свертки «младших» баров в «старший» интервал (толерансы на округления/скользящие границы).

7. **Ручные маркеры данных** (опционально)

    * Возможность отметить интервал как «неверифицируемый/исключённый» (например, деградация API биржи), чтобы не блокировать покрытие.

## Автодокачка (orchestrated)

**Цель:** закрыть «дыры», выявленные проверками, с повторным использованием M4.

Процедура (на серию):

1. Собрать интервалы для докачки из множества `missing` (склеить соседние метки в непрерывные блоки).
2. Для каждого блока вызвать загрузчик (M4) и выполнить `INSERT … ON CONFLICT DO NOTHING`.
3. После вставок — повторная проверка сетки. Если закрыто — обновить `history_group.coverage_start_utc`.
4. Если все обязательные ТФ по связке теперь непрерывны — пересчитать `exchange_instrument_coverage`.

**Идемпотентность:**

* Повторение автодокачки безопасно (дубликаты игнорируются БД).
* Для конкурентного исполнения — один писатель на серию, очереди задач ключуются `(exchangeId, exchangeInstrumentId, timeframeCanon)`.

## Отчёты и статусы

**Per‑series (history_group):**

* `seriesId`, `exchange`, `instrument`, `timeframeCanon`.
* `last_ts`, `min_ts`, `max_ts`.
* `missing_bars_count`, `gaps`: список интервалов (сжатые блоки).
* `ohlc_anomalies_count`, `misaligned_count`.
* `coverage_start_utc (local)` (после фиксов).

**Per‑pair (exchange_instrument):**

* Таблица статусов по всем ТФ (строка — ТФ, столбцы — `missing`, `last_ts`, `coverage_local`).
* Итог: `coverage_start_utc`, `coverage_end_utc`.

**Global:**

* Топ‑N серий с наибольшими пропусками.
* Карта алертов по биржам/символам/ТФ.

## REST API (черновой контракт)

* `POST /api/consistency/check/series`
  Тело: `{ exchange:"okx", instrument:"ETH-USDT", timeframe:"1 hour" }`
  Действие: полный прогон проверок по серии, возврат отчёта.

* `POST /api/consistency/check/instrument`
  Тело: `{ exchange:"okx", instrument:"ETH-USDT" }`
  Действие: проверки по всем сериям связки, возврат агрегата.

* `POST /api/consistency/check/all`
  Действие: выборочно/полностью по всем связкам (с пагинацией/шардированием).

* `POST /api/consistency/repair/series`
  Тело: как для check/series, с флагом `{ autoFill: true }`
  Действие: автодокачка и повторный чек, обновление покрытий.

* `POST /api/consistency/recompute-coverage`
  Тело: `{ exchange:"okx", instrument:"ETH-USDT" }`
  Действие: принудительный пересчёт `exchange_instrument_coverage`.

* `GET /api/consistency/status?exchange=okx&instrument=ETH-USDT`
  Ответ: агрегированный статус по связке.

## Метрики и алерты

**Prometheus:**

* `consistency_missing_bars_total{exchange,tf}`
* `consistency_misaligned_total{exchange,tf}`
* `consistency_ohlc_anomalies_total{exchange,tf}`
* `consistency_checks_duration_ms{exchange,tf}`
* `consistency_autofill_attempts_total{exchange,tf}`
* `coverage_start_utc_seconds{exchange,instrument}`
* `coverage_end_utc_seconds{exchange,instrument}`

**Алерты (примеры):**

* `missing_bars_total > 0` дольше N минут.
* `last_ts` отстаёт от `nowExchange()` более чем на M×Δt.
* `coverage_start_utc` «попятился» назад (регресс качества).

## Планировщик и конкуренция

* Периодическая фоновая задача: сканировать активные серии и запускать **быстрые проверки** (последние K часов/дней) + выборочно полноту.
* Ограничение параллелизма: не более `S` серий одновременно, один писатель на серию.
* Приоритеты:

    1. активные торговые связки,
    2. серии, участвующие в ближайших расчётах индикаторов,
    3. долгий бэкфилл.

---

## Тонкости реализации

* **Δt** берём из канонического ТФ; не понижать в lower‑case и не сравнивать свободно — только строгое соответствие строк каноники.
* Валидация на **границах DST** не нужна — работаем в UTC.
* Докачка всегда работает только закрытыми барами (коннектор M3 обязуется).
* Для больших объёмов:

    * проверка сетки — стриминг и `generate_series` по дням,
    * долгие серии — разбивка по окнам,
    * индексы из M2 достаточны (BTREE по `(history_group_id,timestamp_utc)` + BRIN по времени).

## Приложение A — SLA/политики

* **Отставание «живых» серий**: `last_ts` не старше `k×Δt` (например, `k=2`).
* **Дюрация автодокачки**: лимит N минут на серию; если не закрыто — алерт и перенос в очередь.
* **Аудит вмешательств**: все ручные запуск/остановы докачки логируются с причиной.
